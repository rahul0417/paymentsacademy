# Micro Learning Slide Deck — Design Spec

## Overview

Replace the current flashcard-based micro-learning viewer (`FlashcardViewer.astro`) with a structured, presentation-style slide deck that teaches concepts progressively before testing understanding.

**Route:** `/micro/review/[slug]` (same URL, different experience)

## Design Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Navigation | Horizontal prev/next with progress dots | Presentation-style, familiar UX |
| Slide count | Adaptive per topic | One idea per slide; simple topics ~6 slides, complex topics 10+ |
| Diagrams | Mermaid.js | Consistent with full articles, maintainable |
| Quiz format | One question per slide | Matches "one idea at a time" philosophy |
| Replaces flashcards? | Yes, fully | Slide deck covers explanation + terms + quiz; flashcards are redundant |
| Slide transitions | Instant swap (no animation) | Keeps it snappy; animation can be added later |

## Slide Structure

Every topic deck follows this template. Slides 2–N are adaptive (as many as needed).

| Slide | Type | Content |
|---|---|---|
| 1 | `intro` | Topic title, description, learning objectives (3-5 bullets) |
| 2–N | `concept` | One concept per slide — plain text explanation in simple language |
| (interspersed) | `diagram` | Mermaid diagram on its own slide (sequence, flowchart, etc.) |
| N+1 | `terms` | Key terms with definitions, manually authored in slide data |
| N+2 to N+2+Q | `quiz` | One multiple-choice question per slide with answer + explanation |
| Final | (runtime) | Quiz score summary, restart/back-to-article actions (generated by component) |

### Slide Type Details

**`intro`** — Learning objectives box with peach left border. Sets expectations.

**`concept`** — Prose explanation in accessible language. May include a "callout" box for key insights. One concept per slide — if the article has 3 major sections, that's 3+ concept slides.

**`diagram`** — Mermaid.js diagram rendered client-side. Diagrams always get their own slide so they aren't cramped. Include a short caption/explanation below the diagram. Mermaid is initialized per-diagram using `mermaid.render()` when the slide becomes active (independent of the global MermaidDiagram.astro init guard — the deck manages its own Mermaid instance).

**`terms`** — Glossary cards. Terms and definitions are authored directly in the slide data (not dynamically looked up from glossary.json). Each term shows name + one-line definition.

**`quiz`** — Multiple choice question. User clicks an option, sees correct/incorrect + explanation, then advances. Reuses existing quiz data from `quizzes.ts`.

## Data Schema

### `src/data/microlearning.ts`

```typescript
export type SlideType = 'intro' | 'concept' | 'diagram' | 'terms' | 'quiz';

interface BaseSlide {
  type: SlideType;
}

export interface IntroSlide extends BaseSlide {
  type: 'intro';
  title: string;
  description: string;
  objectives: string[];
}

export interface ConceptSlide extends BaseSlide {
  type: 'concept';
  label: string;        // e.g. "The Big Picture", "Act 1 of 3"
  title: string;
  content: string;      // HTML content — paragraphs, callouts
}

export interface DiagramSlide extends BaseSlide {
  type: 'diagram';
  label: string;
  title: string;
  mermaidCode: string;   // Mermaid diagram source
  caption?: string;      // Optional HTML explanation below diagram
}

export interface TermsSlide extends BaseSlide {
  type: 'terms';
  terms: { term: string; definition: string }[];
}

export interface QuizSlide extends BaseSlide {
  type: 'quiz';
  questionIndex: number; // Index into the topic's quiz questions
}

export type Slide = IntroSlide | ConceptSlide | DiagramSlide | TermsSlide | QuizSlide;

export interface TopicMicroLesson {
  topicSlug: string;
  topicTitle: string;
  theme: string;
  slides: Slide[];
}
```

Note: `score` is NOT a slide type in the data. The score screen is generated at runtime by the component after all quiz slides are answered.

Helpers: `getMicroLessonBySlug(slug)`, `getAllMicroLessonSlugs()`, `getAllMicroLessons()`

Quiz questions are NOT duplicated — the `QuizSlide` references the existing quiz data by `questionIndex`. The viewer component pulls from `quizzes.ts` at render time.

## Component Design

### `MicroLearningDeck.astro`

Replaces `FlashcardViewer.astro`.

**Props:** `topicSlug`, `topicTitle`, `theme`, `slides: Slide[]`, `quizQuestions: QuizQuestion[]`

**Build time:**
- Serializes slide data + quiz questions into `<script type="application/json">`
- For diagram slides: renders Mermaid source into data attributes (NOT `<div class="mermaid">` — avoids conflict with global MermaidDiagram.astro init)

**Client side:**
- Imports `mermaid` dynamically and uses `mermaid.render()` directly per diagram slide (independent of the global `__mermaidInitialized` guard in MermaidDiagram.astro)
- Horizontal navigation: prev/next buttons, progress dot bar at top
- Slide counter: "Slide 3 of 11"
- Renders one slide at a time based on type
- `concept` slides: sets innerHTML from the slide's `content` field
- `diagram` slides: calls `mermaid.render()` on first visit, caches the SVG
- `terms` slides: renders term cards from the `terms` array
- `quiz` slides: shows question + options, handles answer selection, shows explanation
- Score screen (runtime, after last quiz slide): tallies quiz results, saves to localStorage
- Keyboard: left/right arrows navigate

**Progress tracking:** Replaces `flashcardsReviewed` field with `microLearningCompleted` in `ProgressState`. New shape:

```typescript
export interface MicroLearningResult {
  completedAt: number;
  quizScore: number;
  quizTotal: number;
}
```

Also remove the old `microLessonsCompleted` field (leftover from the original content-splitting approach) and `markMicroLessonComplete()` function.

### Styling

- Matches the mockup: white slide card on pale background, racing green headings
- Callout boxes: peach left border, warm background
- Term cards: bordered cards with green term name
- Quiz options: bordered buttons, green for correct, peach for incorrect
- Progress dots: racing green active, lighter for done
- Dark mode: uses existing `html[data-theme="dark"]` CSS variables
- Mobile: full-width slides, large tap targets for nav buttons
